# Phase 5B 设计：公益真实数据直连与 Animal Island 公开页强化

日期：2026-07-09

状态：已由用户确认设计方向，待转为 mission CSV 执行。

## 1. 背景

Phase 5 的公益模块与 Animal Island UI 强化尚未真正闭环。当前本地运行时，公益模块仍通过 Worker 代理请求 `https://api.isoyu.com/gy/api.php`，但上游在本地验证过程中会被 Cloudflare challenge 挡住，导致 Worker 路径无法拿到真实公益数据。页面出现的“李瑾怡”来自 API 文档示例或本地 fallback，不代表真实接口可用。

用户明确指出：公益寻亲信息不能用假数据或文档示例冒充真实展示。若当前无法获取真实数据，宁可隐藏公益模块，也不展示不真实的信息。

同时，当前项目虽然已安装并引入 `animal-island-ui/style`，局部也使用了 Button、Card、Tag 等组件，但页面整体仍偏黑线框、网格纸、监控面板和 demo 卡片视觉。用户希望明显感知到 `guokaigdg/animal-island-ui` 在线 demo 的治愈小岛风格，包括绿色叶纹背景、游戏手型光标、温暖纸质色、圆润组件、飘带/告示牌、自然装饰和轻动效。

本阶段定义为 Phase 5B 修正版：修复公益模块真实数据路径，并把公开页从“组件点状使用”提升为“页面级 Animal Island 视觉系统”。

## 2. 已确认范围

本阶段采用方案 B：公益真实数据修复 + 首页强 Animal Island 化，后台轻量一致化。

包含：

- 公益模块从前台主链路移除 Worker 代理依赖，改为浏览器直连公益 API。
- 只展示真实 API 数据或历史真实缓存；没有真实数据也没有缓存时隐藏公益模块。
- 公开首页、公益模块、作品列表形成明显 Animal Island 小岛风格。
- 后台做轻量视觉一致化，不重构核心 CRUD。
- 执行和验证过程中默认复用用户已在本地运行的 `http://localhost:3000`，Codex 不主动启动项目。

不包含：

- 不把公益模块做成后台 CMS。
- 不新增公益曝光统计。
- 不使用 API 文档示例或本地假数据作为正常展示。
- 不把后台重写为新的多用户系统。
- 不移除现有 live iframe 作品预览能力。
- 不重新设计 D1 数据模型、Worker 鉴权或站点 CRUD 架构。

## 4. 公益数据设计

### 4.1 主路径

公益模块前端直接请求：

```text
GET https://api.isoyu.com/gy/api.php
```

Worker `/public-good` 不再作为公开页主数据路径。它可以保留为未来诊断、fixture 测试或兼容入口，但不能再作为本地运行是否成功的标准，也不能作为前端失败后的假数据兜底来源。

### 4.2 请求策略

浏览器端参考用户提供的旧项目 `CharityAdWidget.tsx` 成熟逻辑：

- 单次 API 返回 1 条公益数据。
- 每轮刷新最多请求 8 次。
- 目标收集 5 条有效数据。
- 按 `id` 去重。
- 单次请求超时控制在约 6500ms。
- 请求间隔约 180ms。
- 连续失败达到 2 次时提前停止。
- 用户刷新页面时不强制每次换一组数据。

具体数值可在实现时以常量集中管理，但默认策略应与以上行为一致。

### 4.3 数据校验

只有通过校验的数据才可进入展示或缓存：

- `id` 必须存在并转为字符串。
- `name` 必须存在并转为字符串。
- `child_pic` 必须存在且是可用图片 URL；若实现决定允许无图记录，则必须在 spec-to-CSV 阶段明确补充验收，但本阶段默认要求有图。
- `url` 如存在，必须是合法 `https://` URL。
- `birth_time`、`lost_time`、`lost_place`、`child_feature` 等文本字段需要 trim 并限制长度。
- 第三方原始 JSON 不直接透传给组件。

### 4.4 缓存策略

前端使用 `localStorage` 缓存真实数据：

- 缓存 key 使用独立版本号，例如 `public-good-real-cache-v2`。
- 默认 TTL 为 6 小时。
- 缓存内容包含版本、过期时间、保存时间和 items。
- 只有真实 API 返回且通过校验的数据可写入缓存。
- 文档样例、本地 fallback、占位内容不得写入真实缓存。
- API 刷新成功后更新缓存。
- API 刷新失败时保留历史真实缓存。

展示规则：

- 有新鲜真实缓存：直接展示缓存，不立即请求或不阻塞渲染。
- 缓存过期但存在历史真实数据：可先展示历史真实缓存，再尝试后台刷新。
- API 刷新成功：替换为新的真实数据。
- API 刷新失败且有历史真实缓存：继续展示历史真实缓存。
- API 刷新失败且无历史真实缓存：公益模块隐藏。

### 4.5 不真实数据禁用

以下内容不得进入正常公益 UI：

- API 文档中的“李瑾怡”示例数据。
- Worker 当前的 `documentedPublicGoodSampleItems`。
- Worker 当前的 `fallbackPublicGoodItems`。
- `app/_lib/api-client.ts` 当前的 `getPublicGoodFallbackBatch()`。
- 任何“公益寻亲信息”“宝贝回家线索”等泛化占位数据。

成功标准是：宁可不显示公益模块，也不显示假的寻亲信息。

## 5. 公开页 Animal Island 设计

### 5.1 品牌与首屏

首页品牌名统一为：

```text
小茄的网站小岛
```

首屏第一眼必须明确是“小茄的网站小岛”，不是通用监控面板或 demo 页面。首屏结构应保持克制：

- 品牌名作为最大视觉信号。
- 一段简短说明，表达这里收录正在运行的网站作品。
- 一个主要行动入口或轻量滚动提示。
- 少量自然装饰和状态提示。
- 不堆叠 dashboard 指标、复杂状态条或大量卡片。

### 5.2 上游 Animal Island 参考

已拉取并研究上游仓库：

```text
.superpowers/references/animal-island-ui
```

关键参考：

- `demo/App.tsx`
- `demo/HomePage.tsx`
- `demo/img/home_bg.webp`
- `demo/img/content_bg_pc.jpg`
- `demo/img/menu_bg.svg`
- `demo/img/guide-bg-line.webp`
- `demo/img/animal_icon.png`
- `AI_USAGE.md`
- `DESIGN_PROMPT.md`
- `skill/SKILL.md`

本项目不应只把 Animal Island 当成按钮库。公开页需要吸收以下页面级元素：

- `Cursor` 全局包裹，启用游戏手型光标。
- `Nunito + Noto Sans SC` 字体。
- 绿色叶纹或自然纹理背景。
- 温暖纸质内容区域。
- 棕色系正文，不使用纯黑文本。
- `Title` 飘带标题或同风格章节标题。
- `Card` pattern、`Tag`、`Button` 等组件形成统一控件语言。
- `Footer` 或同风格底部自然装饰。
- 轻量 hover 浮起、按钮按压、背景慢移动等 2-3 个有意图的动效。

### 5.3 背景与页面壳

当前 `portfolio-surface` 的黑线网格纸背景需要替换为更接近 Animal Island demo 的自然背景：

- 优先使用上游 `home_bg.webp` 或同风格本地化素材。
- 可叠加 `#7DC395` 绿色底色。
- 内容区使用 `#f8f8f0`、`rgb(247, 243, 223)`、`#fffaf0` 等温暖纸色。
- 文本颜色转为 `#794f27`、`#725d42`、`#8a7b66` 等暖棕。
- 避免当前 `#1f2523` 黑绿硬线成为主视觉。

### 5.4 公益模块视觉

公益模块位于首屏之后、作品列表之前。它的语义是“公共告示牌”，不是广告位，也不需要刻意强调“捐出一块作品集曝光位用于公益传播”。

展示形态：

- 一次展示 5 条数据。
- 5 个头像入口 + 1 个详情告示牌。
- 桌面端可左右或上下组合，但必须一眼看到 5 个入口。
- 移动端不依赖 hover，使用点击切换。
- 当前选中头像有 Animal Island 风格描边、浮起或按压反馈。
- 详情牌展示照片、姓名、性别或状态、出生时间、走失时间、走失地点、特征摘要、详情链接。
- `查看详情` 使用 `animal-island-ui` Button 或同风格主按钮。
- 图片加载失败时可显示无图占位，但不能伪造人物数据。

隐藏规则：

- 无真实数据且无历史真实缓存时，不渲染公益模块。
- 隐藏时不留下空白大块或“暂无公益数据”的假公告牌。

### 5.5 作品列表视觉

作品列表继续以 live iframe 为核心，不牺牲真实作品预览。

视觉调整方向：

- 作品卡像小岛上的作品窗口，而不是监控卡片。
- 减少硬黑边、厚重阴影和工程 demo 感。
- 使用温暖纸质面板、圆润边角、柔和棕色文字。
- 状态标签继续保留，但视觉优先级低于作品名称、说明、访问入口。
- Hover 使用轻浮起，不引入高噪声动画。
- 访问网站、查看状态、打开详情等操作继续清晰可达。

## 6. 后台轻量一致化

后台本阶段不重构业务架构，继续保持：

- 单管理员登录。
- 未登录只显示登录入口。
- 登录后站点列表、当前编辑面板、创建、更新、删除、退出登录。
- Worker CRUD 和 D1 数据路径不变。

轻量视觉目标：

- 后台语义从“裸表单 demo”转为“岛务管理所”。
- 使用 Animal Island 字体、暖纸背景、圆润面板、棕色文本。
- 登录、输入、保存、取消、删除、状态标签尽量使用或贴近 `Input`、`Button`、`Tag`、`Card`。
- 删除确认优先使用 `Modal`；如果接入成本过高，可使用本地同风格确认面板。
- 不引入复杂装饰，不降低表单密度和维护效率。
- 移动端必须保证字段、按钮和错误提示不溢出、不重叠。

验收标准是：后台看起来与公开页属于同一套产品，但仍是清楚高效的管理工具。

## 8. 成功标准

Phase 5B 完成后必须满足：

1. 公益模块展示的数据来自真实 API 或历史真实缓存。
2. 无真实公益数据且无真实缓存时，公益模块隐藏。
3. 文档示例、本地 fallback、泛化假数据不再作为正常公益 UI 出现。
4. 用户无需看源码，也能明显感知公开页使用了 Animal Island 小岛风格。
5. 首页品牌名统一为“小茄的网站小岛”。
6. 首页、公益模块、作品列表在视觉上属于同一个温暖小岛产品。
7. 后台完成轻量一致化，但不牺牲 CRUD 效率。
8. 不主动启动本地开发服务器，验证默认复用用户已有 `http://localhost:3000`。

## 9. 后续执行建议

建议后续 mission CSV 拆分为以下任务组：

1. 公益数据 helper：直连 API、规范化、真实缓存、失败隐藏。
2. 公益组件改造：移除假 fallback，接入新 helper，完成 5 头像 + 详情牌。
3. 公开页视觉壳：Cursor、字体、背景、首屏品牌、底部装饰。
4. 作品列表视觉统一：纸质卡片、标签、按钮、hover 动效。
5. 后台轻量一致化：登录、表单、列表、确认交互视觉调整。
6. 测试与浏览器验收：自动化命令、桌面/移动端、真实/无缓存两类公益状态。
